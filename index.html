AI Agents 入門01 / 08
01 · 核心概念

Agent 不只是聊天機器人

AI Agent 是一種以目標為導向，能運用模型判斷、呼叫工具、觀察結果，並決定下一步的系統。

聊天機器人

主要接收問題並產生文字回答，通常停在「回答」。

AI Agent

能拆解任務、使用外部工具、讀取結果，再繼續執行。

例：不只告訴你「哪家航空行李比較多」，還能查官方規定、整理數據並比較差異。

02 · 基本組件

Agent 的四個基本組件

模型 Model

理解任務、推理、規劃與生成內容。

工具 Tools

搜尋、計算、讀寫檔案或呼叫 API，讓系統能採取行動。

指令與護欄

規定目標、權限、格式、禁止事項與停止條件。

狀態 State

保存任務進度、工具結果與必要上下文。

03 · 運作循環

Agent 如何完成任務？

接收目標→規劃→呼叫工具→觀察結果→評估

如果結果不理想，Agent 可以修正計畫，再跑一次循環；如果完成，就停止或交付成果。

關鍵提醒

循環不等於無限重試。要設最大步數、錯誤處理、權限限制與人工確認點。

04 · 流程設計

Workflow、Agent、Graph 有何不同？

Workflow

開發者預先安排步驟與路徑，較可預測。

Agent

模型依狀態動態決定下一步，彈性較高。

Graph

用節點、邊與狀態描述流程，可表達分支與循環。

實務常採混合式：固定流程把關可靠性，局部 Agent 處理需要判斷的工作。

05 · 設計模式

常見 Agent 設計模式

  • Prompt chaining：前一步結果交給下一步。
  • Routing：依輸入類型選擇路徑。
  • Parallelization：把可平行的工作同時處理。
  • Orchestrator-workers：主控者分派任務，再整合結果。
  • Evaluator-optimizer：先產生草稿，再評估與修正。

06 · 應用與風險

能力越強，越需要治理

應用

研究資料整理、客服查詢、程式除錯、行程與行政任務。

風險

幻覺、工具誤用、權限過大、提示注入、循環失控。

防護

來源驗證、最小權限、人工確認、步數上限與完整紀錄。

付款、刪除、寄送等高影響操作，應在執行前取得人類確認。

應用與風險｜Wiki 0407 / 08
07 · 重點回顧

帶走這五個觀念

  1. Agent 以目標為導向，不只是產生文字。
  2. 模型、工具、護欄與狀態共同構成系統。
  3. Agent 透過「規劃—行動—觀察—評估」循環工作。
  4. Workflow 較可控，Agent 較彈性，Graph 描述流程結構。
  5. 可靠的 Agent 必須有驗證、權限與停止條件。
